# Python Rewrite Requirements

This document records the requirements confirmed during the rewrite interview. The implementation specification is derived from this record.

## Confirmed

- Git commit `edc73527e47ec9b5ca7a34f5e35b66b995b62be4` is a catalog of possible capabilities, not a blanket compatibility contract. Rewrite capabilities are reconsidered from the minimum and added only when confirmed.
- Inputs and outputs do not need to remain compatible with the historical shell implementation.
- Collection is operationally read-only as defined in `CONTEXT.md` and ADR 0001.
- Collection is best-effort: attempt independent evidence sources and retain the Raw Evidence that succeeds.
- Classify a delivered bundle as a Partial Collection when any evidence outcome that was actually attempted fails, including an unavailable, nonzero, or timed-out Probe; a selected regular file that cannot be read or copied; a Target Node or SSH cleanup failure; or a configured Kubernetes or Prometheus operation that fails or cannot supply required control data. A capability omitted because its optional configuration is unset, a source path that does not exist, a log outside the Log Evidence Window, an inadmissible link or special object, or a metric intentionally excluded by `metrics_filter_regex` is not an attempted failure and does not by itself make the collection partial.
- Run the initial implementation sequentially. Visit Target Nodes in Node Inventory order and execute each node's Probes in their built-in order; do not provide node or Probe concurrency, a worker pool, or a `--jobs` setting. Concurrency may be reconsidered later without changing the evidence model.
- Execute capabilities in this fixed initial order: collect Target Nodes in inventory order and collect Ceph Cluster Evidence during the configured source node's session; then collect Kubernetes evidence when configured; then collect Prometheus evidence when configured; finally construct the Incident Bundle on the Collection Workstation. Optional workstation capabilities never delay the start of core Target Node collection.
- Workstation orchestration and remote node collection are implemented in Python.
- Package the Collection Workstation application as a standard `pyproject.toml` Python package with the `ceph-incident-bundle` console entry point. Keep production runtime dependencies to the Python 3.10 standard library, support installation into an operator-controlled virtual environment without changing global Python, and organize workstation code into readable focused modules.
- Keep only the remotely transferred collector as the accepted single self-contained source file; the one-file remote constraint does not require the workstation package to collapse into one module.
- Put the collection implementation below `src/ceph_incident_bundle/collect/`: its `__init__.py` exposes the readable top-level `run()` flow, while `node.py`, `node_archive.py`, `kubernetes.py`, `prometheus.py`, and `bundle.py` own their focused capabilities. Keep `cli.py`, shared `inventory.py`, the `generate_inventory.py` command, and self-contained `remote_collector.py` at the package root. The CLI parses and dispatches only; the Inventory Module owns generation, parsing, complete validation, immutable validated configuration values, and exact accepted bytes. The top-level collection flow owns the workstation workspace, explicit destinations, optional-capability decisions, fixed order, final outcome, and command output. It calls Kubernetes or Prometheus only when enabled and passes complete validated settings. Those modules never receive absent configuration or silently decide whether to no-op. The Incident Bundle Module owns final metadata, final-tree structural validation, and atomic publication.
- Have each independent evidence-source collection function return its concrete operator-visible problems as `list[str]`. The `collect` flow uses `problems.extend(...)` for that list and `problems.append(...)` for the single problem created when an unexpected ordinary exception escapes one independent source. Catch such exceptions only around independent Target Node, Kubernetes, and Prometheus attempts so later sources and final packaging are still attempted; do not catch Ctrl-C as an evidence problem. Do not create a fatal domain category: a nonzero command result means no final Incident Bundle could be delivered.
- Keep dependencies one-way: the top-level collection flow may call each capability, only the Node Module depends on Node Evidence Archive admission, peer evidence capabilities do not call one another, and none imports the top-level flow. Do not add a separate workstation Ceph Module; the top-level flow selects the source and Ceph remains in that node's one SSH operation. Keep Remote Node Collector and Kubernetes Probe execution as small explicit implementations on their separate deployment sides.
- Do not introduce a second `collection.py` flow, generic commands package, standalone workspace abstraction, shared Probe or command-runner framework, shared artifact-path abstraction, generic models or errors module, bundle draft, general context object, problem class, reporter callback, mutable status object, severity or exception hierarchy, collector class hierarchy, dependency-injection framework, manager, builder, registry, plug-in framework, `common.py`, or `utils.py`.
- Expose one console command named `ceph-incident-bundle` with exactly two initial public subcommands: `generate-inventory` creates a Node Inventory without collecting evidence, and `collect` performs the full collection and produces the Incident Bundle. Do not expose verifier, redaction, secret-scan, direct-node, or other compatibility subcommands.
- With no options, `generate-inventory` reads `/etc/hosts` and writes `inventory.ini` in the current directory. Permit explicit overrides through `--hosts-file` and `--output`.
- `generate-inventory` must refuse to replace an existing output file and exit nonzero unless the operator explicitly supplies `--force`. With `--force`, replace only the exact resolved output file; never broaden the operation to other files.
- With no options, `collect` reads `inventory.ini` from the current directory, uses the `24h` Log Evidence Window, and writes the Incident Bundle to the current directory. Permit explicit overrides through `--inventory`, `--since`, and `--output-dir`.
- Operators run collection on a Collection Workstation. Node-local evidence is collected only by transferring and executing the Remote Node Collector over SSH on a Target Node.
- Do not provide a user-facing mode that runs the Node Collector directly on the node. Multi-node collection repeats the same SSH-remote collection operation for each Target Node.
- Start exactly one OpenSSH process for each Target Node. Do not use `scp`, SFTP, a second execution session, or one SSH session per Probe. When a Target Node is the configured Ceph source, its Remote Node Collector also attempts the Ceph Cluster Evidence Probes during that same SSH session.
- Keep the Remote Node Collector as one explicit, readable, self-contained Python 3.10 source file. Send that source unchanged on SSH standard input to the fixed remote `python3 -` invocation, followed by end-of-file; do not use a zipapp, base64 wrapper, generated source bundle, or remote installation.
- Reserve the SSH streams for the protocol: standard input contains only the Remote Node Collector source, standard output contains only the gzip Node Evidence Archive bytes, and standard error contains only SSH or Remote Node Collector diagnostics. Invoke local OpenSSH with an explicit Python argument vector and no local shell; pass only fixed flags and already-validated canonical values to the fixed remote invocation.
- Have each Remote Node Collector write a gzip-compressed tar Node Evidence Archive stream to SSH standard output. Do not create or retain a node archive file on the Target Node.
- Receive the complete Node Evidence Archive into a collector-owned regular temporary file on the Collection Workstation. Treat it as untrusted and inspect every member before extracting any member; admit only unique safe relative paths representing ordinary directories or regular files, and reject the entire node archive for any absolute or traversal path, normalized collision, symbolic or hard link, device, FIFO, socket, or other special member. This is structural admission only, not evidence-content validation.
- Extract an admitted Node Evidence Archive only inside that collection's workstation workspace. The Collection Workstation combines admitted node evidence with its Inventory Snapshot, Kubernetes evidence, and Prometheus evidence, and it alone constructs the final Incident Bundle.
- Use only `node/` and, for the configured Ceph source, `ceph/` as top-level paths inside a Node Evidence Archive. After structural admission, map `node/` to `nodes/<inventory_name>/` and map the source node's `ceph/` to the bundle's top-level `ceph/`; the Target Node never chooses or supplies its final `inventory_name` path.
- If SSH cannot connect, is interrupted, or returns an incomplete or structurally rejected Node Evidence Archive, do not extract any member from that archive. Record one concise node-specific failure for standard error and continue the remaining Target Nodes and workstation-local evidence; do not create a transport Capture, preserve SSH standard error in the Incident Bundle, or add transport metadata files.
- When a Node Evidence Archive is complete and structurally admitted but the OpenSSH process exits nonzero, extract and preserve its evidence anyway. Record one concise warning for standard error and classify the overall result as a Partial Collection; do not retain SSH standard error in the Incident Bundle.
- If receiving, staging, admitting, or writing evidence fails for one Target Node, abandon that node's incomplete local result, record a problem, and still attempt every later Target Node, configured workstation evidence capability, and final bundle. Apply the same best-effort rule when one configured Kubernetes or Prometheus collection encounters a workstation-side failure.
- When no Node Evidence Archive can be admitted for a Target Node, omit that node's `nodes/<inventory_name>/` directory entirely. The Inventory Snapshot remains the record that the omitted node belonged to the requested Collection Scope; do not add an empty placeholder directory.
- The operator explicitly supplies the complete Collection Scope through one INI Node Inventory.
- The Node Inventory has a `[common]` section with one `ssh_user` value and a `[nodes]` section mapping each `inventory_name` to an `ssh_address`. The initial supported and generated SSH user is `ssh_user = root`.
- Accept only `[common]`, `[nodes]`, `[ceph]`, `[kubernetes]`, and `[prometheus]`. Reject duplicate sections, unknown sections, unknown fixed keys, duplicate fixed keys, an empty `[nodes]` section, and every `ssh_user` other than `root` before creating a workspace or making a network connection. Keys inside `[nodes]` are the operator-defined `inventory_name` values.
- Validate all configured values before collection: references must resolve; regular expressions must compile with Python semantics; duration and step values must follow their documented grammar; and a Prometheus URL must be an absolute HTTP or HTTPS base URL with a nonempty authority and no query or fragment. Report all discovered startup errors together where practical, then exit nonzero without producing a bundle.
- Configure one timeout for all command-based Evidence Probes as `[common] probe_timeout = 30m`; the inventory generator emits that active default. Accept a positive integer followed by `m`, `h`, `d`, or `w`, and accept the special value `0` to disable Probe timeouts completely.
- Apply `probe_timeout` independently to every node, Ceph, and Kubernetes Probe. On timeout, terminate that Probe, preserve all standard-output and standard-error bytes produced so far, record `outcome: timed_out` with a null exit code in its `result.json`, and continue later Probes. Do not apply this setting to regular-file collection, Node Evidence Archive transfer, Prometheus HTTP, or final Incident Bundle construction.
- Configure SSH connection establishment as `[common] ssh_connect_timeout = 15s`; the inventory generator emits that active default. Convert it to the system OpenSSH `ConnectTimeout` value in seconds. The timeout covers connection establishment and initial handshake only, not node collection or Node Evidence Archive transfer; the special value `0` omits the collector's override and leaves behavior to OpenSSH configuration.
- An `inventory_name` must match `[A-Za-z0-9][A-Za-z0-9._-]*` and becomes the exact directory component below `nodes/`. An Inventory Name Collision includes exact duplicates and pairs that collide under the portable NFC-and-case-fold comparison key, regardless of the Collection Workstation filesystem.
- Values in `[nodes]` accept a hostname, bare IPv4 address, or bare IPv6 address as the `ssh_address`. Do not accept `user@host`, an embedded port, per-node SSH users, keys, or arbitrary SSH options there. The orchestrator forms the OpenSSH destination from the common user and `ssh_address`.
- Do not discover or add SSH targets from Ceph orchestrator output, Kubernetes Nodes, or any other collected cluster evidence.
- Provide a separate subcommand that reads the Collection Workstation's `/etc/hosts` and writes a Node Inventory. Generating an inventory never starts collection.
- The generated inventory enables eligible host entries by default. Exclude loopback addresses and conventional localhost or loopback names; do not emit commented candidates that require manual activation.
- For each eligible `/etc/hosts` line, use only the first hostname after the IP address as the generated `ssh_address`; do not emit the remaining aliases as additional Target Nodes. Derive the generated `inventory_name` from only the first DNS label of that hostname, before its first dot: for example, `mon01-123.aaa.com` becomes `mon01-123 = mon01-123.aaa.com`. Preserve first-seen order and omit later occurrences of an already emitted full hostname. When distinct full hostnames produce an Inventory Name Collision, emit every colliding entry unchanged so the operator can rename them; never drop or automatically suffix a node. Do not use the line's IP address as the generated `ssh_address`; IP addresses remain supported for manually authored entries.
- When the generator emits an Inventory Name Collision, place an `ACTION REQUIRED` comment immediately before every colliding active entry, print every conflict to standard error, and exit nonzero after still writing the complete inventory. The generated duplicate entries remain active so collection must reject them until the operator assigns unique names.
- At the very start of collection, parse the Node Inventory without discarding duplicate keys and reject every unsafe `inventory_name` or Inventory Name Collision. On rejection, report the conflicting entries and exit before creating a collection workspace or Incident Bundle and before invoking SSH, `ceph`, `kubectl`, or Prometheus HTTP.
- The Node Inventory may contain `[ceph] source = <inventory_name>`, where the value must reference a key in `[nodes]`. Run the Ceph Cluster Evidence query set exactly once on that Target Node.
- When generating an inventory, inspect `[nodes]` in preserved `/etc/hosts` order and select the first node whose hostname contains `mon`, `cp`, or `cm`, case-insensitively, as the default `[ceph] source`. This is configuration generation, not runtime capability probing.
- If no generated node hostname matches the Ceph-source naming rule, still emit the `[ceph]` section with a commented empty placeholder, `# source =`. Do not guess another node or emit an active empty value.
- Collection does not replace an unreachable, missing, or failing Ceph source with another Target Node.
- Every remote Probe executes directly as the configured root SSH user. Do not implement `sudo`, privilege escalation, interactive password handling, or special non-root behavior in the initial product boundary.
- The Python orchestrator invokes the system OpenSSH `ssh` executable with an explicit argument vector. Never construct a remote transport through `shell=True` or an interpolated local shell command.
- Use OpenSSH for keys, ports, host verification, jump hosts, and user SSH configuration. Do not add a Python SSH library or implement the SSH protocol in the product.
- Run OpenSSH noninteractively with no pseudo-terminal and with `BatchMode=yes`. Respect the operator's ordinary OpenSSH configuration and known-hosts policy; do not override it to accept a new host key, create a collector-specific trust store, or prompt for a password or confirmation.
- Production code supports CPython 3.10 and newer. Development and tooling may use newer Python versions.
- Collection does not install remote packages, create a remote virtual environment, or change the remote Python installation.
- The Remote Node Collector is invoked with the existing `python3`. If it is missing or older than Python 3.10, record that node as Skipped, classify the overall result as Partial, continue collecting other evidence, and still produce an Incident Bundle.
- Do not fall back to shell collection, install Python, or probe alternate interpreter command names when the required remote runtime is unavailable.
- Do not redact collected content, scan for credentials or secrets, or reject evidence because it may contain sensitive data.
- Do not provide semantic-content, completeness, or safe-to-share bundle verification. Do not classify content by sensitivity or apply special permissions, packaging, or handling because credentials may be present; use the execution environment's ordinary filesystem defaults.
- Collector output admits only ordinary directories and regular files at unique, safe relative paths.
- Do not follow or preserve symbolic links. Do not emit hard-link entries, block or character devices, FIFOs, or sockets. A regular source file may be copied as independent bytes; no link relationship is preserved in the output.
- For copied regular files, preserve only the byte content and mirrored source path. Do not promise to retain source mode, owner, group, modification time, ACLs, extended attributes, or SELinux labels; archive-member metadata produced by the collector workspace is not evidence. This does not remove an explicitly collected metadata listing such as the `/var/lib/ceph` listing.
- If inspecting or copying a selected regular file fails, record one concise node-and-path-specific problem for the Collection Workstation command's standard error, classify the delivered bundle as partial, and continue other files. Do not add an error ledger, failed-file placeholder, or per-file result metadata to the Incident Bundle.
- Reject absolute paths, traversal paths, duplicate paths, and paths that collide after normalization before they can enter a collector workspace or Incident Bundle.
- Treat every archive member name as a POSIX path after the archive reader has resolved standard long-name metadata. Before extracting anything, reject an empty name, an absolute name, any empty, `.` or `..` component, duplicate logical paths, or any collision under a portable comparison key formed by applying Unicode NFC normalization and case folding to each component. Do not rename or normalize an admitted member on disk.
- Reject file-versus-directory conflicts, including two member types at one comparison key and any regular file used as an ancestor of another member. Directory marker syntax may be canonicalized only for comparison. Apply the same single-component NFC-and-case-fold collision rule to `inventory_name` values.
- These structural admission rules are construction-time safety constraints, not semantic-content or completeness verification.
- Command-based evidence is defined as a built-in list of independent Evidence Probes. Each Probe has a stable evidence name, output location, and fixed argument vector.
- Execute Probe argument vectors directly from Python without a shell. Preserve raw stdout, raw stderr, and the actual exit status without modifying, normalizing, or judging the content. Minimal parsing of a successful control response is allowed only to schedule the confirmed dependent crash, Pod-log, or Prometheus requests; that parsing never replaces or changes the Raw Evidence.
- A missing command or nonzero exit is recorded for that Probe and does not stop later Probes or other Target Nodes.
- Do not accept arbitrary operator-supplied commands in the initial product boundary.
- Every Target Node attempts a Node Baseline. Each item remains independent and best-effort.
- Node identity and resources include hostname, current UTC time, `uname -a`, `uptime`, `lscpu`, `free -h`, and `ps auxfww` evidence.
- Node filesystem and storage evidence includes `df`, `lsblk`, `iostat`, `pvs`, `vgs`, and `lvs`.
- Node network evidence includes `ip addr`.
- Node kernel and service evidence includes `dmesg` and failed systemd units.
- Node container evidence includes `podman ps -a` and `docker ps -a`.
- Copy `/etc/os-release`, `/etc/hosts`, and `/etc/resolv.conf` only when the source itself is a regular file. Do not follow a symbolic link to obtain any of these files.
- Time synchronization, journald and `/var/log`, `/var/lib/ceph`, Ceph cluster, Rook or Kubernetes, and Prometheus evidence are not part of the Node Baseline; decide each capability separately. `cephadm` evidence is outside the product boundary.
- Every Target Node attempts Time Synchronization Evidence without first detecting or selecting an active implementation.
- Chrony Probes are `chronyc tracking` and `chronyc sources -v`. The ntpd Probe is `ntpq -pn`.
- systemd-timesyncd Probes are `timedatectl status`, `timedatectl show-timesync --all`, `timedatectl timesync-status`, and `systemctl status systemd-timesyncd`.
- Attempt to copy `/etc/chrony.conf`, `/etc/chrony/chrony.conf`, `/etc/ntp.conf`, `/etc/systemd/timesyncd.conf`, and regular `*.conf` files directly under `/etc/systemd/timesyncd.conf.d/`. Copy only regular files and never follow symbolic links.
- A missing time command, service, directory, or configuration file is recorded and does not prevent other time evidence. Time synchronization journal evidence belongs to the separate journald capability.
- Recursively consider files under `/var/log` and copy eligible regular files as unchanged raw bytes while preserving their relative directory structure.
- Do not follow symbolic links or collect special filesystem objects from `/var/log`. Do not decompress, classify, merge, rename, redact, or parse log contents.
- One Log Evidence Window parameter is shared by `/var/log` and journald collection.
- Expose the window as `--since DURATION`, defaulting to `24h`. Accept a positive integer followed by `m`, `h`, `d`, or `w`, such as `30m`, `24h`, `7d`, or `2w`; do not accept absolute or fuzzy date expressions.
- At the start of log collection on each Target Node, calculate one cutoff from that node's current clock. Use that same cutoff for both `/var/log` mtime selection and journald. Do not correct or align clocks between nodes. Reading source mtime for this selection does not require preserving it in the copied artifact.
- Determine `/var/log` eligibility approximately from each regular file's modification time. Do not inspect timestamps within a file to decide eligibility.
- If a regular file's modification time falls within the Log Evidence Window, copy the entire file unchanged even when some of its contents are older than the window. Skip the entire file when its modification time is older than the cutoff; apply the same rule to plain, compressed, and binary files.
- Failure to inspect or copy one log file is recorded and does not stop other log evidence.
- Each Target Node attempts one all-system Journal Evidence Probe equivalent to `journalctl --since <node-cutoff> --no-pager --utc --output=short-iso-precise`.
- Do not add separate Ceph, time synchronization, or other per-unit journal captures. Preserve the all-system stdout as-is and record stderr and exit status under the ordinary Probe model.
- Do not exclude `/var/log/journal` from raw filesystem collection. Regular binary journal files whose modification time is in the window are copied unchanged in addition to the human-readable Journal Evidence.
- Do not implement a log byte limit, member-count limit, or `unlimited` option in the initial product boundary. The Log Evidence Window is the only proactive scope reduction for logs.
- Attempt to preserve every eligible log file in full. If source reading, workspace capacity, or transport fails, record the failure and retain whatever other evidence completed successfully.
- Collect Ceph Cluster Evidence through direct `ceph` invocations only. Do not invoke `cephadm`, `cephadm shell`, `sudo ceph`, or any runner-detection or fallback sequence.
- Attempt the historical JSON query set: `status`, `health detail`, `versions`, `df detail`, `osd tree`, `osd df`, `osd dump`, `osd perf`, `osd blocked-by`, `pg stat`, `pg dump`, `pg dump_stuck`, `mon dump`, `quorum_status`, `mgr dump`, `orch host ls`, `orch ps`, `orch device ls --wide`, `config dump`, and `crash ls`, each with `--format json-pretty` where supported by the historical command.
- Also attempt the historical text query set: `status`, `health detail`, `osd tree`, and `orch ps`.
- From a successful `crash ls` result, attempt `ceph crash info` for at most the first ten crash identifiers. A failed Ceph query is preserved under the ordinary Probe model and does not stop later Ceph queries.
- Do not invoke `cephadm` anywhere in the product, including for Target Node evidence.
- Every Target Node attempts Node-local Ceph Evidence. Record a recursive metadata listing of `/var/lib/ceph` containing relative path, filesystem type, size, and modification time, without admitting link or special-object semantics into collector output.
- Copy all regular files under `/etc/ceph` unchanged, including keyrings or files containing credentials. Never follow symbolic links.
- Under `/var/lib/ceph`, copy only regular files named `ceph.conf`, `config`, `*.conf`, or `*.config`, unchanged and without following symbolic links.
- Do not copy Ceph daemon databases, OSD block data, or other `/var/lib/ceph` file contents outside the configuration-file rule.
- Collect Rook Cluster Evidence with direct `kubectl` invocations only.
- Invoke `kubectl` on the Collection Workstation where the collection command itself runs. Do not run `kubectl` over SSH, search Target Nodes for it, or define a Kubernetes source node.
- Require `[kubernetes] context = <context>` in the Node Inventory before attempting Rook Cluster Evidence. Pass it to every Kubernetes Probe as the explicit `kubectl --context <context>` argument vector; never interpolate it through a shell and never fall back to the ambient current context.
- The inventory generator emits a `[kubernetes]` section with the inactive placeholder `# context =`. If context remains unset, explicitly skip all Rook Cluster Evidence while continuing every other collection capability.
- Attempt `kubectl get pods -o wide`, time-sorted Events, and YAML for `CephCluster`, `CephBlockPool`, `CephFilesystem`, and `CephObjectStore` in the external consumer namespace.
- For the initial Rook log implementation, preserve `kubectl get pods -o json` from both the consumer and operator namespaces, deduplicating the request when the configured namespaces are equal. Parse only Pod and container identity/status fields needed to schedule log Probes.
- Attempt logs within the shared Log Evidence Window for every listed Pod and every named regular, init, and ephemeral container in both configured namespaces. Use one direct `kubectl logs` Probe per Pod/container so its raw output remains separate; when the preserved Pod status reports a container restart, also attempt its previous log. Give these dynamic Probes safe sequence-based names and retain the exact namespace, Pod, and container in their argument vectors.
- The initial supported Rook topology is the external Ceph cluster pattern. Keep the external consumer namespace used for Rook objects, Pods, and Events separate from the operator namespace used to locate and read operator logs; both are explicit inventory fields.
- Use `[kubernetes] consumer_namespace = rook-ceph-external` and `[kubernetes] operator_namespace = rook-ceph` as the generated defaults. The consumer namespace selects Rook objects, Pods, Events, and logs; the operator namespace selects operator-side Pods and logs.
- Restrict Kubernetes access to read-only retrieval commands such as `kubectl get` and `kubectl logs`. Never use `kubectl exec`, `cp`, `apply`, `create`, `patch`, `replace`, `delete`, `rollout`, `scale`, `port-forward`, or a Rook toolbox or Pod-hosted `ceph` command. A failed Kubernetes query is preserved under the ordinary Probe model and does not stop later queries or Target Node collection.
- Prometheus Evidence is optional and collected directly from the Collection Workstation only when the Node Inventory configures a Prometheus URL. An absent URL skips the entire capability without affecting other evidence.
- Use the shared `--since` Log Evidence Window for Prometheus range evidence. Preserve API responses without redaction or semantic metrics analysis.
- Configure the endpoint as `[prometheus] url = <base-url>`. The inventory generator emits `[prometheus]` with the inactive placeholder `# url =`.
- Use Python 3.10 standard-library HTTP directly and issue GET requests only. Encode query parameters with Python URL utilities; do not invoke `curl` or add a third-party HTTP dependency.
- Do not mask or reject credentials embedded in the configured Prometheus URL, and do not apply special handling because credentials are present.
- Prometheus collection attempts build information and active-target API responses, then discovers scrape job names.
- Select jobs matching `ceph|node` case-insensitively and preserve API discovery order. For each selected job, discover metric names within the shared time window, deduplicate exact repeated names by first occurrence, apply `metrics_filter_regex`, and issue one `query_range` request for every admitted `(job, metric)` pair. Query the pair through escaped PromQL label matchers for both `job` and `__name__`; the same metric in two jobs therefore produces two independent Prometheus Captures.
- Configure the metric-name selector as `[prometheus] metrics_filter_regex = <regex>`. Apply it to discovered metric names with Python regular-expression semantics. An empty value performs no metric-name filtering and therefore admits every discovered metric; the inventory generator emits `metrics_filter_regex =` as that active default.
- Configure range resolution as `[prometheus] query_step = 15s`; the inventory generator emits that active default. Use the configured value unchanged for every `query_range` request. Prometheus range collection is fidelity-first: do not enlarge `query_step` because the requested time window is long or the estimated response is large, and do not impose a collector-side sample-count, response-size, metric-count, or total-byte limit.
- Configure Prometheus network waiting as `[prometheus] request_timeout = 5m`; the inventory generator emits that active default. Treat it as a blocking network-operation timeout rather than a total request-duration limit: a response that continues making progress may run indefinitely. Accept `0` to disable the timeout.
- Stream each Prometheus response incrementally into its `response` file without a byte limit. If a network timeout or later read error occurs, retain every response byte already received, record the structured error in `result.json`, and continue independent requests.
- Preserve every HTTP response as raw evidence. Parse only the response fields required to schedule dependent job, metric, and range requests; do not evaluate whether returned metrics are healthy or semantically correct.
- A failed or unparseable response is recorded and prevents only the requests that depend on its data. Continue independent Prometheus requests and all non-Prometheus collection.
- Give every attempted Prometheus HTTP GET its own Prometheus Capture directory containing `response` and `result.json`. Preserve the response body byte-for-byte in `response`, including bodies returned with non-success HTTP status; use an empty regular file when no response body was received. Record the exact requested URL, UTC start and finish times, nullable HTTP status, and any structured transport error in `result.json`.
- A base Prometheus `result.json` contains exactly `url`, `started_at`, `finished_at`, `outcome`, `http_status`, and `error`. A metric-name discovery Capture additionally contains exactly `job_name`; a range Capture additionally contains exactly `job_name` and `metric_name`. `outcome` is `received` or `failed`. `http_status` is an integer or null, while `error` is null or an object containing string `kind` and `message` fields. HTTP, Prometheus API, required control-response parsing, timeout, and transport failures use `outcome: failed` while retaining every response byte received.
- Place fixed Prometheus Captures directly at `prometheus/<request-name>/`, specifically `prometheus/buildinfo/`, `prometheus/targets/`, and `prometheus/job-values/`; do not add a `requests/` or `probes/` layer. Place per-job metric-name Captures below `prometheus/metric-names/<sequence>/` and per-pair range Captures below `prometheus/query-range/<sequence>/`, where each sequence is a one-based collection-order number padded to a minimum of six decimal digits without imposing an upper bound.
- Do not place a metric name in a filesystem path. Record its complete value in that range Capture's `result.json`, while the unmodified metric-discovery response remains Raw Evidence. The numeric directory avoids filesystem component-length, character, and normalization collisions; its presentation may change in a future bundle layout without changing the evidence meaning.
- Deliver each collection as one gzip-compressed tar Incident Bundle with the `.tar.gz` suffix. A Partial Collection is still packaged and delivered instead of being discarded.
- For the collection subcommand, exit zero whenever the final Incident Bundle is successfully created, including for a Partial Collection. Reserve standard output for one final line containing the bundle's path and either `(complete)` or `(partial)`; write progress, problems, warnings, and failures to standard error. Exit nonzero only when startup rejection or a workstation failure prevents delivery of any final bundle.
- Name the archive and its single root directory `ceph-incident-bundle-<STARTED_AT_UTC>`, using the collection start instant formatted as compact UTC `YYYYMMDDTHHMMSSZ`; append `.tar.gz` only to the archive filename.
- After the Node Inventory passes startup checks, preserve its exact input bytes as the root-level Inventory Snapshot `inventory.ini`. Do not normalize, regenerate, or redact it.
- Write a minimal root-level `collection.json` containing exactly the collector version, UTC collection start and finish times, the effective `--since` duration string, and the overall `complete` or `partial` outcome. Do not turn it into a file manifest, artifact index, error ledger, hash list, validation result, or completeness claim.

Under `files/`, mirror each admitted absolute source path after removing only its leading slash, such as `/etc/hosts` to `files/etc/hosts` and `/var/log/messages` to `files/var/log/messages`.

For repeated dynamic Probes, append a one-based collection-order number padded to a minimum of six decimal digits, such as `crash-info-000001`; do not place an externally supplied identifier directly in the path.
